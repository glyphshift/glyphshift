# Glyphshift

**给 Windows 软件和游戏翻译界面，用自己的字典，也可以让 AI 帮忙。**

[下载软件](https://www.yuelili.com/apps/glyphshift) · [在线文档](https://docs.yuelili.com/glyphshift) · [GitHub Releases](https://github.com/Yuelioi/glyphshift/releases) · [English](README.en.md)

Glyphshift 在目标软件运行时读取文字，查找字典，再把译文交给目标软件显示。收集原文、填写译文、调整字体都在同一个工作流里完成，不需要修改目标软件的安装文件。

它适合给常用工具整理界面翻译，也适合尝试翻译游戏菜单和对白。能翻译哪些地方，取决于目标软件的文字显示方式和适配器支持情况。

## 开始使用

1. **安装并打开 Glyphshift。** 从上面的下载入口获取 Windows 安装包。
2. **新建工作流，设置软件。** 选择运行中的程序、浏览程序文件，或从最近记录里选。选好后会自动填写工作流名称；适配器默认全选，不确定就先保持默认。
3. **添加字典。** 创建新字典或选择已有字典，确认原文和译文语言。需要收集新文字时，选一本作为“写入”字典。
4. **点“开始运行”。** 如果目标软件还没打开，会显示“等待软件启动”；打开后会尝试连接。
5. **点“查看文字”，边用边翻译。** 在目标软件里打开菜单、面板或推进对白，让工作流收集原文。自己填译文，或用 AI 补全，再到目标界面检查效果。

每个工作流对应一个软件。其他软件可以新建或复制工作流；不同软件的工作流可以同时运行，不用再维护单独的软件库或探针任务。

## 工作流怎么运行

| 你做的操作 | 工作流会怎样 |
| --- | --- |
| 开始运行，软件还没打开 | 等待软件启动 |
| 关闭目标软件 | 回到等待；重新打开后尝试连接 |
| 关闭“收集新原文” | 不再收集新文字，已有译文和字体替换继续工作 |
| 停止运行 | 停止这个工作流，再打开目标软件也不会自动连接，直到再次点开始 |
| 停止没有成功 | 显示停止失败，可以再次停止，不会直接当作已经停好 |

顶部、列表和详情显示同一份运行状态。切回工作流页面或回到 App 前台时会刷新，后台也会定期检查；历史上收集过文字，不代表软件现在仍在运行。

译文保存后，目标画面不一定马上重画。可以在“任务操作”里刷新目标文字；有些菜单需要重新打开，有些对白需要继续播放。停止后画面何时恢复也取决于适配器，部分组件会留在目标进程中，直到目标软件退出。

## 字典怎么搭配

字典只管保存原文、译文和语言等信息，可以独立编辑、分享，也可以被多个工作流复用。字典可以使用任意源语言和目标语言。

一个工作流可以选多本字典：

- **写入：** 新收集的原文和工作流 AI 补全结果放进这本字典。
- **其他字典：** 只要已经有相同原文，就不会往写入字典重复添加，即使那边的译文还是空的。
- **优先级：** 从上往下找译文；同一句话有多份译文时，先用排在前面的。用上下箭头调整顺序。

字典和工作流的文字列表都能筛选已翻译、未翻译，也可以隐藏命中跳过规则的条目。跳过规则统一在设置里管理。

### 导入和导出

- **导入 JSON、UTF-8 CSV、SRT。** 可以一次选多个文件，分别生成字典，或合并成一本，再确认名称和语言。
- **SRT 提取字幕文字。** 可以提前整理、翻译字幕字典，再让工作流使用；这不会直接改写原字幕文件。
- **导入已有字典。** 可以只追加新条目、覆盖相同原文，或确认后替换全部条目。
- **导出 JSON、CSV。** JSON 适合保留字典元数据，CSV 方便用表格工具整理。SRT 目前只支持导入。

CSV 需要保留 `source`（原文）和 `translation`（译文）两列。译文可以为空；原文不能为空，同一文件里不能重复。格式有问题时，会提示文件名、原因，以及能定位到的行号。

## AI 补全

支持 OpenAI、Anthropic、Gemini、兼容 OpenAI 接口的服务、Ollama，以及本机已登录的 Codex 订阅。

先在设置里添加 AI 配置，填服务地址和模型并测试连接，再到字典或工作流里使用 AI 补全。分批条数、最多同时请求数、超时和重试都可以调整。翻译速度取决于模型、设备和服务响应，自动补全不保证实时出结果。

- 只补还没翻译的内容，命中跳过规则的条目会跳过。
- 任务在后台运行，可以继续浏览其他页面；批次、进度、耗时和服务返回的 Token 用量可以随时查看。
- 同时运行一个翻译任务，任务内按 AI 配置的并发数发请求；多个工作流的自动补全会排队。
- 自动补全间隔支持 0～60 秒。0 表示发现新内容后尽快处理，后台仍有 250ms 的最小检查间隔。
- 目标软件自然退出时，不再开始新一轮，但当前一轮可以完成；主动停止工作流会取消它自己的自动补全任务，不影响手动字典任务或其他工作流。
- 重启 Glyphshift 不会自动恢复 AI 请求。

**使用云端 AI 时，待翻译文字会发送给你选择的服务。API Key 目前明文保存在本机配置中。** 使用本机 Codex 订阅会消耗相应订阅额度；不使用 AI 时，也可以完全手动维护字典。

## 字体和设置

字体与字号配置放在工作流里：可以设置默认字体、默认字号缩放，也可以给某本字典单独设置覆盖，复用字典时不用一起带走这些显示设置。

设置页还可以管理最近软件、常用字体、按语言配置的缺字回退字体和语言列表。实际字体替换、字号缩放和缺字补全能力取决于适配器，不能保证所有软件都支持。

首次使用会把本机已有的微软雅黑、宋体、黑体、Segoe UI 等推荐字体加入常用。已有用户可以在字体设置中点“添加推荐字体”，不会覆盖自己的收藏。

Glyphshift 自身支持简体中文和 English，提供深色、浅色和跟随系统主题；这些不会限制字典可以翻译的语言。应用更新提示可以在设置中关闭。

## 哪些软件能用

目前的适配器覆盖传统 Windows 文字、GDI+、部分 DirectWrite、Qt Widgets、Qt Quick、GTK 3 / Pango、raylib、MonoGame、Unity Mono 等文字路径。VGUI 本地化查询和 CatSystem2 对话适配仍属于实验功能，需要更多游戏验证。

支持某个框架，不代表这个框架做的软件就能全部翻译。例如，Unity Mono 的支持不等于支持 IL2CPP；图片里的字、自绘字形和已经缓存成纹理的文字也可能无法替换。具体版本和能力范围请看 App 中的适配器说明。

如果没有效果，先确认目标软件已打开、两者权限匹配，再检查是否收集到了原文。抓到了文字但没有变化时，尝试重新打开对应界面；换过驻留适配器或 Runtime 版本后，可能需要完整退出并重开目标软件。

## 文档与发布

日常使用看[在线文档](https://docs.yuelili.com/glyphshift)，仓库内的文档入口是 [docs/index.md](docs/index.md)。

项目已配置 [Release Action](.github/workflows/release.yml)：推送 `vMAJOR.MINOR.PATCH` 标签后，校验应用版本、构建 Windows 安装包，并把同一份代码中的 `docs/` 打包成 `docs.zip`。Release 附件包括安装包、候选清单、文档包和 SHA-256 校验文件。

文档站可以绑定 Release 的 `docs.zip` 自动同步；Action 本身负责打包和上传附件。维护和绑定步骤见[文档发布说明](scripts/docs-publishing.md)。
