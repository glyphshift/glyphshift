# 翻译配置与自动翻译

## 添加翻译配置

进入“设置 → 翻译配置”，点“添加翻译配置”。

Glyphshift 可以使用大模型翻译服务，也可以使用专用机器翻译服务。选择服务预设后，软件会填入默认地址和模型或部署；只有服务要求时才需要填写 API Key，再点“测试连接”。预设内容仍可手动修改。

想少折腾账号时，可以直接用 DeepSeek，或者在本机运行 LibreTranslate。LibreTranslate 预设默认连接 `http://127.0.0.1:5000`，自建实例默认不需要 API Key；如果连接的实例启用了 API Key，再在配置里填写即可。

百度翻译使用通用文本翻译 API，需要 APP ID 和 Secret Key。为兼容标准版的单次长度与 QPS，Glyphshift 默认只开 1 个并发，并把一批词条控制在较小的源字符范围内。Google Translate 使用 Cloud Translation Basic v2，需要 API Key；Google 的接口原生接受字符串数组，Glyphshift 单次最多发送 128 条，并继续按请求字符数拆批。

Microsoft Translator 使用 Text Translation REST API 2026-06-06。部署名称填 general 时使用微软 NMT；如果 Azure 中配置了 Foundry LLM 或 Custom Translator deployment，可把对应 deploymentName 填在同一位置。全局 Translator 资源通常不用填写 Region；区域或多服务资源按 Azure 门户中的 Region 填写。

测试连接会试着翻译一句话，最多等 30 秒，不自动重试。云端服务可能收费；本地模型第一次加载可能比较慢，加载好后可以再试。

## 自动翻译字典

在字典或工作流里点“自动翻译”，确认要翻译的内容后开始。默认只处理空译文，不覆盖你已经填好的翻译。

任务在后台运行，不会强制跳到任务页面。需要查看进度、批次、耗时或实际用量时，打开翻译任务即可。

正在写入的目标字典暂时不能手动修改，其他字典照常使用。

## 自动补全

先在设置里调整“自动补全间隔”，再到工作流里勾选“自动补全”。

- **0 秒：** 发现新内容后尽快开始，后台至少间隔 250 毫秒检查，避免不停空转。
- **1～60 秒：** 隔这么久检查一次。

取消勾选后，不再发起后续任务。已经发出的任务需要在翻译任务里停止。0 秒不代表译文瞬间返回，仍要等内容被收集和翻译服务完成请求。

自动补全会排队，不会每次检查都新开一个任务。一个翻译任务内部可以同时发送多个请求，条数、源字符数和并发上限由所选翻译 Provider 决定。

目标软件正常退出时，已经开始的任务会继续完成，等软件重新连接后再处理新内容。主动停止工作流会停止它发起的自动补全任务，不影响你单独创建的翻译任务。重启 Glyphshift 后不会自动续跑之前的任务。

## 提示词与模型能力

使用 OpenAI、Claude、Gemini、Ollama 等大模型 Provider 时，可以在翻译配置中修改翻译提示词，告诉模型希望使用的语气和专有名词。格式和顺序由软件处理，不用自己写。

专用机器翻译 Provider 不显示不适用的提示词和思考设置。LibreTranslate 直接批量发送源语言、目标语言和文本，不需要模型字段；Microsoft Translator 的 NMT 模式直接发送源语言、目标语言和文本，Foundry LLM deployment 由微软 Translator 服务负责模型调用。

## 用量和速度

任务只显示翻译服务实际返回的用量，不估算供应商未报告的计费量。大模型 Provider 可以返回输入、缓存输入、输出、思考与总 Token；Microsoft Translator NMT 返回源字符用量，LLM deployment 还可以返回 Token 用量。

不同 Provider 的批量限制也不同。例如 Microsoft Translator NMT 可以使用更大的条目批次；LLM deployment 会自动收紧单批条数。Glyphshift 会按 Provider 的批量策略拆分任务，不需要手工拆分字典。

列表翻译不会默认“一条一请求”。Google Translate 和 LibreTranslate 可以在一个 HTTP 请求中直接发送字符串数组；Microsoft Translator 发送 `inputs[]`。百度通用翻译的 `q` 是一个文本字段，因此 Glyphshift 会把当前批次的多条原文用换行合成一次请求，再按返回的 `trans_result[]` 顺序映射回原词条。每个批次都检查返回条数，数量不一致时该批次失败，不会把译文错写到别的词条。大模型 Provider 则把一批词条作为结构化数组交给模型，并要求返回同样数量、同样顺序的译文数组。

本地模型太慢时，先看是否大部分计算落在 CPU 上，再考虑换更小的模型。普通界面翻译一般先关闭额外思考。

选中的待翻译原文会发给所选翻译服务。敏感内容不要交给不信任的服务。

翻译配置中的 API Key 目前保存在本机配置文件里，没有加密。不要把配置文件当作普通字典分享。

## 跳过规则

在设置的“文字过滤”里统一调整，不在每个翻译配置里单独设置。升级时会保留旧 AI 配置与默认选择。数字、网址、路径等内容可以跳过；字典里也能选择隐藏这些条目，但不会删除。
